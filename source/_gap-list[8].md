# CID Security Rebuild — Gap List (Phase 1.3)

Consolidated from `_source-pack.md` §12 and `_outline-delta.md`. Every item below is something the 30-IT-question set demands but the source pack does not currently answer.

**Blocking** = IT reviewers will reject the deliverable without this. **Non-blocking** = nice to have, can ship the doc with a "documented gap" note.

**Column meanings:**

- **IT Q** — which of the 30 IT questions (see `~/projects/personal/cid-knowledge/proposals/security-doc-rebuild-plan.md`) this gap blocks. `implicit` = no specific IT question, but a security reviewer will ask anyway.
- **Where it surfaces** — the page(s) in `~/projects/personal/cid-docs/docs/` that will need this answer when drafted.
- **Question** — phrased as if it came from a prospective customer's IT / security team in an RFP or security questionnaire. Answering this question on the listed page is what closes the gap.
- **Answer** — your input. A sentence or two is enough; include source/person if relevant (e.g. "confirmed with X on 2026-05-13"). Leave blank if you don't know — that signals Phase 1.4 needs to chase it.

Fill the **Answer** column for each row you can. Once complete, we proceed to folding answers back into `_source-pack.md` and on to Phase 2.

**Acronyms used below:**

- **MFA** — multi-factor authentication
- **SSO / SAML / OIDC** — federated identity standards (Single Sign-On / Security Assertion Markup Language / OpenID Connect)
- **IdP** — Identity Provider (e.g. Okta, Azure AD, Ping)
- **CVE / CVSS** — Common Vulnerabilities and Exposures / scoring system
- **SLA** — Service Level Agreement
- **SIEM** — Security Information and Event Management (e.g. Splunk, QRadar, Sentinel — where customer security teams send logs)
- **SOC 2 / ISO 27001 / FedRAMP / IRAP** — third-party security/compliance attestations customers ask for
- **21 CFR Part 11 / EU Annex 11** — FDA and EU regulations on electronic records and electronic signatures in pharma. CID's position on these is *not* answered in the security doc itself; instead the doc should point to Agilent's existing CDS/OpenLab regulatory-position document. G-11 is asking where that document lives and what it says.
- **AD** — Microsoft Active Directory (Windows domain authentication)
- **TPM** — Trusted Platform Module (hardware crypto chip used by Secure Boot, BitLocker, etc.)
- **LUKS** — Linux Unified Key Setup (standard Linux disk-encryption format)
- **VPC** — AWS Virtual Private Cloud
