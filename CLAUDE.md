# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cid-docs` is the customer-facing documentation site for the **Agilent Connected Instrument Device (CID)** and **CID Hub** (the SaaS control plane that activates CIDs, distributes software/config, and mediates Agilent support tunnels). It is a content repository: nearly all work is writing and editing Markdown, not code. The site is built with **Docusaurus 3.10** (React 19, TypeScript).

## Commands

```bash
npm install            # install deps (Node >= 18; CI and Docker use Node 24)
npm start              # dev server with live reload at http://localhost:3000
npm run build          # static build into ./build — RUN THIS to validate changes
npm run serve          # serve the production build locally
npm run typecheck      # tsc (config files only; not part of the build)
npm run clear          # clear the .docusaurus cache if the dev server misbehaves
```

There is no test suite. **`npm run build` is the validation gate** — `onBrokenLinks: 'throw'` in `docusaurus.config.ts` makes the build fail on any broken internal link or cross-reference, so a clean build is the definition of "passing." There is no CI; run the build locally before pushing.

## Authoring documentation

When writing or reviewing any Markdown under `docs/`, **use the `documentation-style-guide` skill** — it carries the voice, structure, Diátaxis, and Agilent terminology rules this content follows. The "Documentation Domain Context" section below feeds that skill.

### Conventions

- **All published content lives in `docs/`**, served at the site root (`routeBasePath: '/'`). A page at `docs/security/remote-access.md` is served at `/security/remote-access`.
- **Frontmatter**: pages use `title`, `description` (used for SEO and search), `sidebar_position`, and sometimes `slug` or `toc_max_heading_level`. The H1 is the `#` heading in the body, not the frontmatter title.
- **Sidebar is autogenerated** from the folder structure (`sidebars.ts`). Control ordering with `sidebar_position` in frontmatter; control section labels, ordering, and landing pages with `_category_.json` in each folder (`generated-index` for an auto index, or `doc` to point at an `index.md`).
- **Images** go in `docs/img/` and are referenced with relative paths (e.g. `./img/cid.jpg` or `../img/data-flow.svg`). Every image needs descriptive alt text.
- **Diagrams**: architecture diagrams are authored as `.excalidraw` source files committed alongside their exported `.svg` in `docs/img/`. Edit the `.excalidraw` and re-export the `.svg`; reference the `.svg` in pages. Mermaid is also enabled for inline diagrams.
- **Internal links**: link by route path (e.g. `/howto`, `./security-model#trust-boundaries`). Because broken links throw at build time, always `npm run build` after changing links, slugs, or filenames.
- Use Docusaurus admonitions (`:::tip`, `:::caution`, etc.) for callouts.

### Content organization (Diátaxis-style)

- `docs/start/` — getting started / register & activate
- `docs/howto/` — task-oriented procedures, grouped into subfolders (`account/`, `monitoring/`, `onboarding/`, `operations/`, `setup/`, `updates/`)
- `docs/reference/` — system requirements, compatibility, hardware/bundle, release notes
- `docs/security/` — security model, architecture, data flow, remote access, compliance (audience: IT/security reviewers)
- `docs/troubleshooting/` — symptom-first index (`index.md`) routing to per-failure pages
- `docs/legal/` — EULA, acceptable-use policy

### `support/` is internal-only

The `support/` directory (e.g. `factory-reset-runbook.md`) holds internal support runbooks. It lives **outside `docs/`**, is not built, and is not published. Keep do-not-publish material here, never under `docs/`.

## Deployment

- **Cloudflare Pages** builds the `security` branch — build command `npm run build`, output dir `build`. Set the production URL and base path at build time via env vars: `DOCS_URL=https://<project>.pages.dev DOCS_BASE_URL=/ npm run build`. These default to `/` when unset (see `docusaurus.config.ts`).
- There is no CI and no other deploy target; Cloudflare is the only place the site is published.

## Documentation Domain Context

This context configures the `documentation-style-guide` skill.

- **Vendor / product identity**: Agilent. The products documented are the **Connected Instrument Device (CID)** — a pre-configured, single-instrument controller appliance for OpenLab CDS — and **CID Hub**, the multi-tenant SaaS control plane that activates and manages CIDs. Related Agilent products referenced: OpenLab CDS, OpenLab Server, OpenLab ECM, the OpenLab Instrument Controller (AIC). Each CID controls exactly one instrument (1:1 pairing).
- **Publishing platform**: Docusaurus (Markdown + MDX). Honor the frontmatter, admonition, sidebar, and relative-link conventions above. Internal links must resolve at build time.
- **Audiences**: lab administrators / IT operators (how-to, onboarding, updates) and IT/security reviewers (the `security/` and `reference/` sections, which are written more formally and technically).
